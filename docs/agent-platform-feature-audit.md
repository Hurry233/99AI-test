# Agent 平台功能审查清单

本清单用于把产品从“应用广场 / 插件市场”逐步收敛为 ChatGPT 风格的 Agent 平台。原则是：**先隐藏低价值入口、保留数据兼容；再把高频能力升级为原生 Agent 工具；最后删除后端与管理端遗留模块。**

## 可以去掉或默认关闭

| 模块 | 当前问题 | 建议动作 | 风险 |
| --- | --- | --- | --- |
| 聊天侧边栏旧插件市场 | 会把用户带回“插件卡片/商城”心智，且与模型原生能力、Agent 工作台重复 | 默认关闭 `legacyPluginMarketplace`，仅保留回滚开关 | 仍有存量插件数据时需要迁移说明 |
| 前台“应用广场”命名 | 产品定位落后，和 Agent 平台目标不一致 | 统一改为 Agent 工作台 / Agent 中心 / 能力分类 | 只改展示层，接口和表结构暂不重命名 |
| 管理端“插件应用 / App 分类”文案 | 管理员创建的是 Agent 能力，但表单仍像 App 商店 | 统一管理端菜单和表单文案 | 后续再做实体和 API 重命名 |
| `@` 搜索“应用”提示 | 该入口本身有价值，但文案应从应用切到 Agent | 保留快捷搜索，改为 `@ 搜索 Agent` | 无明显风险 |
| Mermaid 作为“插件”暴露 | Mermaid 是常用图表工具，不应依赖插件市场心智 | 作为原生图表工具展示，保留内部兼容字段 | 后续可把 `currentPlugin` 抽象为 `currentTool` |

## 应该优化而不是删除

1. **Agent 工作台**：保留现有 app 数据模型承载 Agent，但补充能力分类、任务编排、模型/文件能力说明。
2. **会员能力**：会员限制可保留，但文案改成“会员专属 Agent 能力”。
3. **文件上传 / 图片上传 / 联网搜索 / 深度思考**：这些是 Agent 平台核心能力，应继续强化为输入框原生工具。
4. **后台 Agent 配置**：当前表单字段仍叫 `appModel`、`catId` 等，短期不改接口；中期建议新增 Agent DTO 层做兼容映射。

## 后续重构建议

- 新增 `Agent` 领域命名层：前端类型 `AgentItem` 映射后端 `AppEntity`，避免继续扩散 `App` 命名。
- 将 `currentPlugin` 拆成 `currentTool`，并把 Mermaid、联网搜索、深度思考、MCP 工具纳入统一工具栏模型。
- 后端 `PluginModule` 进入迁移期：先只给管理端灰度使用，确认无流量后再移除路由和实体。
- 将 Agent 工作台的搜索、分类、收藏接口独立为 `/agent/*`，旧 `/app/*` 保留 1 个版本周期做兼容。
- 为 Agent 能力增加埋点：打开工作台、选择 Agent、使用 @ 搜索、上传文件、启用联网/深度思考，便于判断哪些旧能力可以彻底删除。
